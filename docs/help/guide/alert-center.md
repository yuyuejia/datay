# 告警中心

DataY 告警中心在任务**失败**或**超时**时自动生成告警，并通过站内信、邮件、Webhook 通知相关人员。
任务恢复或人工处理后，告警事件自动闭环，避免同类问题长期停留在待处理列表。

告警中心适合放在任务上线之后使用：先配置服务邮箱和通知渠道，再按任务范围配置告警规则，
最后在告警事件列表中认领、处理和复盘。

## 功能概览

| 能力 | 说明 |
| --- | --- |
| 告警事件 | 查看待处理 / 已认领 / 已恢复事件，支持按状态、级别和关键字筛选 |
| 告警规则 | 定义什么任务、什么事件、什么级别触发告警，以及通知谁 |
| 通知渠道 | 站内信内置；邮件和 Webhook 需要单独创建并启用 |
| 服务邮箱 | 邮件通知依赖的 SMTP 发件配置，同时用于系统账号邮件 |
| 投递记录 | 查看外部渠道每次发送的状态、尝试次数和错误原因 |

## 进入告警中心

登录后从顶部导航 **任务运维 → 告警中心** 进入，也可以点击右上角通知铃铛中的告警消息跳转。

页面顶部展示三类事件数量：

- **待处理**：新产生、尚未处理的告警
- **已认领**：已被某个用户接手处理的告警
- **已恢复**：任务恢复或人工标记恢复的告警

页面包含三个页签：

1. **告警事件**：查看和处理告警
2. **告警规则**：维护触发条件和接收人
3. **通知渠道**：维护邮件和 Webhook

## 推荐配置流程

```text
① 配置服务邮箱（SMTP）
        │
        ▼
② 新建通知渠道并点击「测试」
        │
        ▼
③ 新建告警规则，选择接收人和渠道
        │
        ▼
④ 制造一次任务失败，验证告警和投递记录
```

如果只需要站内信，可以跳过第 ①、② 步：站内信是内置能力，不需要配置任何渠道。
邮件和 Webhook 则必须在第 ② 步创建并启用，并在规则中勾选。

## 配置服务邮箱（SMTP）

服务邮箱是 DataY 的**发信基础设施**，用于发送账号激活、密码重置等系统邮件，也用于告警的邮件渠道。
邮件渠道只负责配置“发给谁、抄送谁、主题前缀”，真正的 SMTP 连接由服务邮箱提供。

> 服务邮箱未配置好时，站内信仍然可用；只有邮件渠道会发送失败。

### 配置文件位置

邮件配置分布在 `datay-web/src/main/resources/config/` 下：

- `application.yml`：`jhipster.mail.from`，系统邮件的发件人地址
- `application-dev.yml` / `application-prod.yml`：`spring.mail.*`，SMTP 服务器、端口、账号、密码和协议参数

仓库中的 `application-dev.yml` 和 `application-prod.yml` 默认已经预留了企业邮箱示例。
下面把两处配置合并展示：

```yaml
spring:
  mail:
    host: smtp.qiye.aliyun.com
    port: 465
    username: datay@yuyuejia.com.cn
    password:        # 默认是空的，必须补上 SMTP 密码或客户端授权码
    properties:
      mail:
        smtp:
          auth: true
          ssl:
            enable: true
          starttls:
            enable: false

jhipster:
  mail:
    from: datay@yuyuejia.com.cn
```

生产环境请把 `password` 替换为真实的 SMTP 密码或邮箱服务商提供的客户端授权码，
并确保 `from` 是 SMTP 账号允许使用的发件地址。**不要把真实密码提交到 Git 仓库。**

### 使用环境变量覆盖

推荐在部署环境中通过环境变量注入，而不是修改仓库里的配置文件：

```bash
export SPRING_MAIL_HOST=smtp.qiye.aliyun.com
export SPRING_MAIL_PORT=465
export SPRING_MAIL_USERNAME=datay@yuyuejia.com.cn
export SPRING_MAIL_PASSWORD='your-smtp-password'
export SPRING_MAIL_PROPERTIES_MAIL_SMTP_AUTH=true
export SPRING_MAIL_PROPERTIES_MAIL_SMTP_SSL_ENABLE=true
export SPRING_MAIL_PROPERTIES_MAIL_SMTP_STARTTLS_ENABLE=false
export JHIPSTER_MAIL_FROM=datay@yuyuejia.com.cn
```

修改配置文件或环境变量后需要重启服务才能生效。多个实例部署时，每个可能发送邮件的实例都需要同样的配置。

### 465 与 587 端口

不同邮箱服务商对加密方式的要求不同，关键是让 `port` 与 SSL / STARTTLS 开关匹配：

| 常见端口 | 加密方式 | 建议配置 |
| --- | --- | --- |
| `465` | 隐式 SSL | `ssl.enable: true`、`starttls.enable: false` |
| `587` | STARTTLS | `ssl.enable: false`、`starttls.enable: true` |
| `25` | 明文或服务端策略升级 | 仅内网可信环境使用，公网不建议 |

例如使用 `587` 端口时：

```yaml
spring:
  mail:
    host: smtp.example.com
    port: 587
    username: alert@example.com
    password: your-password
    properties:
      mail:
        smtp:
          auth: true
          ssl:
            enable: false
          starttls:
            enable: true
```

如果端口和加密方式不匹配，常见表现是连接超时、SSL 握手失败或认证失败。

### 发件人地址

邮件渠道发送时按以下顺序确定发件人：

1. `jhipster.mail.from`
2. `jhipster.mail.from` 为空时，回退到 `spring.mail.username`
3. 两者都为空时，回退到 `datay@localhost`（仅用于兜底，生产环境不建议依赖）

建议显式配置 `jhipster.mail.from`，并与 SMTP 登录账号或服务商允许的发件别名保持一致，
否则可能被邮件网关拒绝。

### 验证服务邮箱

1. 确认服务已重启并加载新的 SMTP 配置。
2. 进入 **告警中心 → 通知渠道**，新建一个邮件渠道并点击 **测试**。
3. 检查目标邮箱是否收到带渠道邮件前缀的测试邮件（新建渠道默认前缀为 `[DataY告警]`）。
4. 如果没有收到，检查目标邮箱的垃圾箱、应用日志中的邮件异常，以及 SMTP 服务商的安全设置。

测试消息只用于验证渠道，不会生成告警事件，也不会写入告警投递记录。

## 通知渠道

点击 **告警中心 → 通知渠道 → 新建渠道** 创建邮件或 Webhook 渠道。
每个渠道都有名称、编码、类型和启用开关；编码留空时系统会自动生成，保存后也可以手动维护。

> 站内信始终发送，不需要也不应该创建“站内信渠道”。

### 站内信

站内信是内置能力：

- 不需要 SMTP，也不需要通知渠道
- 接收人由告警规则中的 **站内信接收人** 决定
- 消息会出现在右上角通知铃铛中，未读数会提示
- 点击通知会打开告警中心，便于继续查看和处理

如果规则没有选择接收人，保存时会自动使用 `role:ROLE_TENANT_ADMIN`，即发送给租户管理员。

### 邮件渠道

邮件渠道通过服务邮箱发送 HTML 邮件。创建时需要填写：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 渠道名称 | 是 | 例如“运维邮件组” |
| 渠道编码 | 否 | 留空自动生成；租户内唯一，只允许字母、数字、下划线和中划线 |
| 渠道类型 | 是 | 选择 **邮件** |
| 收件人 | 是 | 多个地址用逗号、分号或空格分隔 |
| 抄送 | 否 | 多个地址用逗号、分号或空格分隔 |
| 邮件前缀 | 否 | 默认 `[DataY告警]`，最终主题为“前缀 + 空格 + 告警标题” |
| 启用 | 是 | 停用后，即使规则选择了该渠道也不会投递 |

邮件内容包含告警级别、任务名称、任务编码、实例编码、事件类型、触发时间和告警正文；
失败 / 超时告警的正文中还会附带任务错误日志。

### Webhook 渠道

Webhook 适合对接企业微信机器人、钉钉机器人、飞书机器人或自建告警平台。创建时需要填写：

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 渠道名称 | 是 | 例如“值班群机器人” |
| 渠道编码 | 否 | 留空自动生成；租户内唯一 |
| 渠道类型 | 是 | 选择 **Webhook** |
| Webhook 地址 | 是 | 必须以 `http://` 或 `https://` 开头，且能从 DataY 服务端访问 |
| 签名密钥 | 否 | 填写后启用 HMAC-SHA256 签名 |
| 自定义请求头 | 否 | JSON 对象，例如 `{"Authorization":"Bearer xxx"}` |
| 启用 | 是 | 停用后规则不会向该地址投递 |

请求格式：

- 方法：`POST`
- `Content-Type`：`application/json; charset=utf-8`
- `User-Agent`：`DataY-Alert-Center/1.0`
- 连接超时：5 秒；请求超时：默认 10 秒
- 只有 HTTP `2xx` 响应才视为成功

请求体示例：

```json
{
  "id": "019a0f00-0000-7000-8000-000000000001",
  "title": "[P1] 任务失败：每日订单同步",
  "content": "任务名称：每日订单同步\n任务编码：order_sync\n任务类型：SQL\n...",
  "severity": "P1",
  "status": "FIRING",
  "sourceType": "JOB",
  "eventType": "FAILED",
  "jobCode": "order_sync",
  "jobName": "每日订单同步",
  "instanceCode": "order_sync_20261023_001",
  "firstSeen": "2026-10-23T10:00:00+08:00",
  "lastSeen": "2026-10-23T10:00:00+08:00",
  "eventCount": 1
}
```

如果配置了签名密钥，DataY 会计算请求体的 HMAC-SHA256，并增加请求头：

```text
X-DataY-Signature: sha256=<十六进制签名>
```

接收方验签时，必须使用**原始请求体字节**参与计算，不能先解析 JSON 再重新序列化，否则签名会不一致。

### 测试通知渠道

在通知渠道列表中点击 **测试**：

- 邮件渠道会按当前邮件前缀发送一封标题为“DataY 告警渠道测试”的邮件
- Webhook 会收到一条 `eventType` 为 `TEST` 的测试消息
- 页面会提示测试成功；失败时会显示具体错误信息，可结合服务端日志继续排查

测试会按渠道当前配置立即发送，正式告警仍要求渠道处于启用状态，并且被规则选中。

### 启停与删除渠道

- **停用**：保留配置和历史投递记录，但新告警不再投递到该渠道
- **启用**：恢复投递，无需重新编辑规则
- **删除**：从渠道列表移除；已绑定该渠道的规则不会自动清理引用，后续外部投递会跳过该渠道

删除渠道前建议先确认没有启用中的规则依赖它。

## 告警规则

点击 **告警中心 → 告警规则 → 新建规则** 配置触发条件。
一条规则由“事件 + 范围 + 级别 + 接收人 + 渠道”组成。

### 规则字段

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 规则名称 | 是 | 建议写清楚业务范围，例如“核心任务失败告警” |
| 规则编码 | 否 | 留空自动生成；租户内唯一，只允许字母、数字、下划线和中划线 |
| 告警事件 | 是 | 可多选 **任务失败（FAILED）**、**任务超时（TIMEOUT）** |
| 告警级别 | 是 | `P0 紧急`、`P1 重要`、`P2 一般`，默认 `P1` |
| 任务类型 | 否 | 例如 `SQL`、`SHELL`、`ETL`、`DAG`；留空表示全部类型，匹配时不区分大小写 |
| 静默时长 | 否 | 默认 30 分钟，范围 0–1440 分钟 |
| 站内信接收人 | 否 | 通过弹窗选择角色或用户；不选时默认租户管理员 |
| 通知渠道 | 否 | 可多选已创建的邮件 / Webhook 渠道；不选则只发站内信 |
| 启用 | 是 | 停用后该规则不再参与匹配 |

任务类型必须与任务实例的类型完全一致（忽略大小写），例如任务类型是 `SQL` 时填写 `SQL`；
填写不存在的类型不会匹配任何任务。

### 选择站内信接收人

接收人必须通过 **选择接收人** 弹窗选择，不支持手工输入文本。弹窗中：

- **角色**：显示角色名称，适合“运维组”“租户管理员”等群体
- **用户**：显示登录名，适合指定到具体负责人
- 支持搜索、多选和取消已选项
- 保存后以标签形式展示；点击标签上的关闭按钮可以移除

接收人解析规则：

- 角色会展开为当前租户内拥有该角色的**已激活用户**
- 用户会按登录名匹配当前租户内的**已激活用户**
- 只显示当前租户内的用户，不会跨租户发送
- 规则没有选择接收人时，保存后使用 `role:ROLE_TENANT_ADMIN`
- 如果默认的租户管理员角色下没有用户，系统会兜底发送给该租户前 20 个已激活用户，
  避免默认规则完全无人接收

### 静默时长

静默时长用于抑制告警风暴：

- 同一规则、同一任务、同一事件类型在静默期内重复失败，只累计事件次数，不重复发送通知
- 超过静默时长后再次失败，会更新最近触发时间并重新发送通知
- 设置为 `0` 表示不做静默抑制，但同一实例的重复状态事件仍会被去重

### 通知渠道

- 站内信**始终发送**，不需要在通知渠道中勾选
- 邮件和 Webhook 需要在规则中勾选对应的渠道
- 规则只能选择已创建的渠道；渠道被停用后，规则勾选也不会产生外部投递
- 一条规则可以同时选择多个外部渠道，每个渠道独立发送并独立记录投递结果

### 默认规则

为了开箱可用，系统提供默认告警：

- 当租户下**没有任何告警规则**时，首次发生任务失败 / 超时会自动创建默认规则“任务失败告警”
- 默认事件为 `FAILED`、`TIMEOUT`，级别 `P1`，静默 30 分钟
- 默认接收人为 `role:ROLE_TENANT_ADMIN`，仅发送站内信，不绑定外部渠道
- 系统租户预置了“系统任务失败告警”，接收人为 `admin`

默认规则同样可以在列表中编辑、启停或删除。如果租户下还有其它规则，删除默认规则后系统不会自动补回；
当所有规则都被删除后，下一次失败会重新生成默认规则。

### 自定义规则与默认规则的优先级

- 启用的自定义规则命中时，**优先使用自定义规则**
- 只有在没有自定义规则命中时，默认规则才作为兜底
- 多条自定义规则同时命中时，每条规则都会产生一条告警事件

因此，如果希望某类任务使用专属接收人，可以新建一条任务类型更具体的自定义规则，
默认规则不会重复发送同一事件。反之，如果发现同一失败产生多条告警，通常是因为多条自定义规则同时命中。

## 告警事件

### 触发条件

- 任务最终状态为 **失败（FAILED）** 或 **超时（TIMEOUT）**
- 只处理**顶层任务**；DAG 子任务失败由父任务统一告警，子任务不单独产生告警
- 规则必须处于启用状态，并且事件类型、任务类型都匹配

### 事件内容

告警内容包含：

- 任务名称、任务编码、任务类型
- 实例编码、执行节点
- 开始时间、结束时间、状态
- 失败 / 超时任务的错误日志

错误日志由任务执行节点读取后随状态事件上报，集群模式下 master 不需要访问 worker 的本地日志文件。
读取时会优先提取 `ERROR`、`Exception`、`Caused by`、`失败`、`异常`、`错误` 等错误相关行；
如果没有任何匹配行，则退化为最后一个日志文件的末尾内容。

日志读取限制：

- 单个日志文件只读取末尾 128 KB
- 最多读取 100 个相关日志文件
- 告警中的错误日志最终最多保留 8000 字符，过长时保留末尾内容

如果无法读取到日志，告警内容中会显示“未获取到任务日志”。

### 事件状态

| 状态 | 界面名称 | 说明 |
| --- | --- | --- |
| `FIRING` | 待处理 | 新告警，或尚未被认领 |
| `ACKNOWLEDGED` | 已认领 | 已被用户接手处理 |
| `RESOLVED` | 已恢复 | 任务成功恢复或人工标记恢复 |

操作方式：

- **认领**：将待处理告警标记为已认领，并记录认领人
- **恢复**：手工标记为已恢复，并记录恢复人
- **详情**：查看任务信息、完整告警内容和投递记录

### 自动恢复

任务成功后，系统会自动把**同一任务编码（jobCode）**下所有未恢复的告警标记为已恢复，
恢复人记为 `system`。当前版本不会额外发送“恢复通知”，只在告警事件中更新状态。

如果任务成功后告警仍未恢复，先确认实例的 `jobCode` 是否与告警一致，再手工标记恢复。

### 去重与计数

同一租户、同一规则、同一任务编码、同一事件类型的未恢复告警会合并为一条事件：

- 同一实例的重复状态事件不会重复计数
- 新的失败实例会累计 `次数`
- 静默期内的重复失败只累计次数，不重复发送通知
- 超过静默期后再次失败会重新通知，并更新最近触发时间

## 投递记录与重试

在告警详情中可以看到外部渠道的投递记录：

| 字段 | 说明 |
| --- | --- |
| 渠道 | 邮件或 Webhook |
| 目标 | 邮件收件人或 Webhook 地址 |
| 状态 | 发送中、成功、失败 |
| 次数 | 实际尝试次数 |
| 错误 | 最后一次失败原因 |

外部渠道最多尝试 **3 次**，重试间隔约为 1 秒和 2 秒。站内信不产生外部投递记录；
如果详情提示“本次告警没有外部渠道投递记录”，通常表示规则只配置了站内信，或外部渠道已被停用 / 删除。

投递失败不会影响告警事件本身，也不会反向影响任务执行。修复渠道后可以点击 **测试** 验证，
后续新告警会继续投递。

## 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 任务失败但告警列表没有记录 | 规则停用；事件类型未勾选；任务类型不匹配；只有 DAG 子任务失败 | 检查规则启用状态和匹配条件，确认父任务是否最终失败 |
| 有站内信但没有邮件 | 规则未选择邮件渠道；渠道被停用或删除；SMTP 配置错误 | 查看详情中的投递记录，再到通知渠道点击测试 |
| 邮件测试提示认证失败 | `password` 为空或不是授权码；用户名与发件人不匹配 | 补齐 SMTP 密码 / 客户端授权码，确认 `jhipster.mail.from` |
| 邮件连接超时或 SSL 握手失败 | 端口与 SSL / STARTTLS 配置不匹配；网络或防火墙限制 | `465` 用 SSL，`587` 用 STARTTLS；检查出站网络 |
| 邮件进了垃圾箱 | 发件域名未配置 SPF / DKIM，或收件方策略拦截 | 配置邮箱服务商的域名认证，或将发件人加入白名单 |
| Webhook 测试超时 | DataY 服务端访问不到地址；HTTPS 证书不受信任 | 从服务端检查 DNS、网络、防火墙和证书；确保返回 2xx |
| Webhook 返回 401 / 403 | 自定义请求头中的令牌不正确 | 更新鉴权头后重新测试 |
| 告警内容显示“未获取到任务日志” | 执行节点没有日志文件、读取权限不足或日志路径不匹配 | 检查执行节点 `log` 目录和任务日志写入情况 |
| 静默期内没有收到新通知 | 距上次通知未超过静默时长 | 等待静默结束，或把静默时长调整为 0 |
| 同一失败产生多条告警 | 多条自定义规则同时命中 | 合并规则，或收窄任务类型 / 事件类型 |
| 任务已成功但告警仍是待处理 | 实例 `jobCode` 与告警不一致，或状态事件未到达 | 核对任务编码，必要时手工标记恢复 |

## 最佳实践

- **站内信作为兜底**：即使暂时没有配置邮箱，也建议保留站内信接收人，保证告警不会完全丢失。
- **按团队使用角色**：值班组、运维组用角色接收，只有明确责任人时才使用具体用户。
- **分级配置渠道**：`P0` / `P1` 可同时发邮件和 Webhook，`P2` 只发站内信，减少噪音。
- **合理设置静默**：频繁重试的任务建议设置 10–30 分钟静默，避免重复通知淹没真正的故障。
- **变更后立即测试**：修改 SMTP 或渠道配置后，先点击 **测试**，再依赖正式告警。
- **不要提交密码**：SMTP 密码、Webhook 密钥和鉴权头应通过环境变量或密钥管理系统注入。
