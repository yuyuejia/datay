# 数据权限

**目标**：按角色限制用户可以访问的**维度成员**和**数据行**，让同一张报表、同一个指标对不同角色呈现不同的数据范围。

导航：**右上角用户菜单 → 数据权限**（仅管理员可见）。

> 数据权限控制的是“能看到哪些数据”，不是“能看到哪些菜单/按钮”。菜单与接口权限仍由「角色管理」控制。

## 两个层面

数据权限页面包含两个页签，分别控制两类查询：

| 页签 | 控制对象 | 典型场景 |
| --- | --- | --- |
| **维度数据权限** | 指标查询中的维度成员范围 | 华东区域经理只能看到华东门店的销售额 |
| **数据集数据权限** | 已保存数据集的输出行 | 看板里的订单数据集只显示当前部门的数据 |

两类权限可以叠加：看板中的**指标数据集**会先按维度成员范围过滤，再按数据集行级条件过滤。

两个页签使用同一组条件运算符：

| 运算符 | 说明 | 取值 |
| --- | --- | --- |
| 等于 / 不等于 | 精确匹配 | 单值 |
| 属于 / 不属于 | 多值匹配 | 多个值 |
| 模糊匹配 | `LIKE` 匹配 | 单值 |
| 大于 / 大于等于 / 小于 / 小于等于 | 数值或日期比较 | 单值 |
| 区间 | `BETWEEN` | 起始值和结束值 |
| 为空 / 不为空 | 判断是否为空 | 无需取值 |

## 入口与基本操作

1. 点击右上角用户菜单，选择 **数据权限**。
2. 页面顶部可以按**角色**筛选；不选择角色时展示全部规则。筛选只影响列表展示，规则归属仍以每条规则中选择的角色为准。
3. 在「维度数据权限」或「数据集数据权限」页签中新增、编辑、删除规则。
4. 列表中的「启用」开关可以临时停用规则；停用后该规则不参与查询。
5. 新增时选择角色；编辑时角色不可修改，需要换角色请新建规则。

保存并启用后，后续查询按新规则执行；已经打开的看板或查询页面需要重新查询后才会反映新的数据范围。

> `ROLE_ADMIN` 默认不受任何数据权限限制。为管理员角色配置的规则不会生效。

没有配置规则的已登录用户，以及所有规则都被停用的用户，不会被追加数据范围限制。

## 指标数据权限（维度成员范围）

页面上的页签名称是「维度数据权限」，它限制的是**指标查询**能看到哪些维度成员。

### 控制范围

配置生效后，以下场景都会自动叠加当前用户角色的维度成员范围：

- 公共指标查询面板
- 智能问数
- 看板中的指标数据集
- 数据集管理中的指标数据集预览

规则在服务端查询指标时拼入 SQL，前端无法通过修改查询参数绕过。

### 配置步骤

1. 进入「维度数据权限」页签，点击 **新增范围**。
2. 选择角色。
3. 选择要控制的**维度模型**，只能选择 `DIMENSION` 类型的模型。
4. 添加「成员条件」：选择维度字段、运算符和成员值。
5. 需要多个可选值时继续点击 **+ 添加 OR 条件**。
6. 保存后确认「启用」开关处于打开状态。

成员值下拉来自该维度模型的成员数据，支持关键字搜索和分页选择。

### 条件组合规则

- **同一个维度内**的多个条件按 **OR** 组合，满足任意一个即可。
- **不同维度之间**按 **AND** 组合，必须同时满足。
- 同一个角色对同一个维度配置了多条规则时，这些规则的条件也会合并后按 OR 处理。
- 用户自己设置的业务限定、时间范围与数据权限范围之间是 **AND** 关系。

示例：

```text
角色：ROLE_REGION_EAST
维度：门店
条件：区域名称 IN (华东, 华南)

维度：品类
条件：一级品类 = 家电
```

最终效果是：**华东或华南区域，并且属于家电品类**的数据。两个维度之间是 AND。

### 维度未关联时

指标数据权限依赖事实模型与维度模型的关联关系。如果某个指标绑定的事实表没有关联被控制的维度：

- 默认策略是 `SKIP`：跳过这条维度限制并记录告警，查询仍会执行。
- 可以设置 `datay.security.data-scope.missing-dimension-policy=DENY`，让这类查询直接失败，避免权限被绕过。

生产环境建议使用 `DENY`，并在上线前确认所有需要管控的指标事实表都已经关联对应维度。修改配置后需要重启服务生效。

## 数据集数据权限（行级过滤）

「数据集数据权限」限制的是**已保存数据集**输出结果中可见的行。

### 控制范围

- 看板中通过 `refId` 引用已保存数据集时生效。
- 在数据集管理中预览**已保存**数据集时生效。
- **不生效**于看板里内嵌的数据集，也不生效于数据集编辑器中**未保存定义**的实时预览。

> 如果希望某个看板受数据集权限控制，请在数据集管理中先保存数据集，再在看板里通过引用方式使用它，不要直接内嵌数据集定义。

### 前置条件

1. 数据集已经保存。
2. 数据集已经有字段信息。新数据集需要先预览一次生成字段，否则页面会提示「该数据集暂无字段信息」。
3. 条件字段必须是数据集的**输出字段**；底层表里有、但没有输出到数据集结果的字段不能直接用于权限条件。
4. 字段名需要是合法的 SQL 标识符，建议使用字母或下划线开头、只包含字母、数字和下划线的英文别名。

### 配置步骤

1. 进入「数据集数据权限」页签，点击 **新增规则**。
2. 选择角色和数据集。
3. 添加「行级条件」：选择输出字段、运算符和值。
4. 条件值可以从数据集的字段取值中搜索选择，支持分页；也可以直接输入候选值之外的取值。
5. 需要多个可选值时点击 **+ 添加 OR 条件**。
6. 保存并启用。

### 条件组合规则

- 同一个数据集内的多个条件按 **OR** 组合。
- 同一个用户有多个角色、且这些角色都配置了该数据集规则时，多个角色的规则取**并集**，仍然按 OR 合并。
- 不同数据集之间互不影响，各自使用各自的规则。
- 看板筛选器条件在数据集内部执行，数据权限条件在外层包裹，两者同时生效。

> 数据集行级条件目前只支持 OR 组合，不支持直接配置“字段 A 与 字段 B”的 AND。如果业务需要跨字段 AND，建议在 SQL 数据集中先拼出一个组合字段（例如 `部门|区域`），再对这个组合字段配置 `IN` 条件。

### 指标数据集与 SQL 数据集

| 数据集类型 | 指标数据权限 | 数据集数据权限 | 执行方式 |
| --- | --- | --- | --- |
| SQL 数据集 | 不涉及 | 生效 | 在数据集 SQL 外层包裹 `SELECT * FROM (...) dp_dataset WHERE (...)` |
| 指标数据集 | 生效 | 生效 | 指标查询先按维度成员范围过滤，再在结果外层包裹数据集行级条件 |

因此，如果一个看板使用指标数据集，两类权限会同时起作用；如果使用 SQL 数据集，则只会应用数据集行级条件。

### Elasticsearch 限制

SQL 数据集绑定的数据源如果是 Elasticsearch，并且该数据集配置了行级数据权限，查询会直接报错：

```text
Elasticsearch 数据源暂不支持数据集行级数据权限
```

需要改用支持 SQL 包裹的关系型/分析型数据源，或者移除该数据集的数据权限规则。

## 生效范围速查

| 使用场景 | 指标数据权限 | 数据集数据权限 |
| --- | --- | --- |
| 公共指标查询 | 生效 | 不涉及 |
| 智能问数 | 生效 | 不涉及 |
| 看板引用已保存的指标数据集（`refId`） | 生效 | 生效 |
| 看板引用已保存的 SQL 数据集（`refId`） | 不涉及 | 生效 |
| 看板内嵌指标数据集 | 生效 | 不生效 |
| 看板内嵌 SQL 数据集 | 不涉及 | 不生效 |
| 已保存数据集预览 | 指标数据集生效 | 生效 |
| 数据集编辑器未保存预览 | 指标数据集生效 | 不生效 |

## 与角色、管理员的关系

- 规则按**角色**生效：用户拥有该角色，才会应用对应规则。
- 用户同时拥有多个角色时，各角色的规则会合并；数据集条件取并集，指标条件按维度合并。
- `ROLE_ADMIN` 不受限制；为管理员配置规则没有实际效果。
- 用户没有登录、没有任何启用规则，或所有相关规则都被停用时，不追加限制。
- 删除角色前需要先删除该角色的数据权限规则；删除数据集时，系统会自动清理该数据集上的权限规则。

## 常见问题

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 管理员仍能看到全部数据 | 管理员默认例外 | 使用普通角色账号验证 |
| 配置了指标权限但查询结果没有变化 | 事实表没有关联被控制的维度，默认策略 `SKIP` | 在维度建模中关联维度，或将缺失策略设为 `DENY` 后排查 |
| 看板内嵌数据集不受数据集权限控制 | 内嵌数据集没有已保存数据集 `refId` | 改为引用已保存的数据集 |
| 规则保存失败，提示数据集暂无字段 | 数据集还没有生成字段信息 | 先在数据集管理中预览一次 |
| 查询时报“数据集权限字段不存在” | 数据集输出字段被修改，旧规则引用了已不存在的字段 | 重新编辑规则，选择当前存在的字段 |
| 查询时报“数据集字段名不合法” | 输出字段名包含空格、中文或特殊字符 | 在数据集中为字段设置合法的英文别名 |
| 角色删除失败 | 该角色仍有数据权限规则 | 先删除该角色的规则，再删除角色 |
| 配置了多个条件，结果比预期更宽 | 同一数据集内的多个条件按 OR 组合 | 检查是否误以为多个条件是 AND；必要时改用组合字段 |
| 看板使用 SQL 数据集时报 Elasticsearch 不支持 | 数据集配置了行级条件，但数据源是 Elasticsearch | 改用支持 SQL 的数据源，或移除该数据集规则 |

## 安全建议

- 数据权限在查询服务端执行，不依赖前端隐藏；但仍需配合数据库账号权限，直接访问物理表的场景不受这里控制。
- 上线前用真实业务角色账号验证指标查询、智能问数和看板，不要只用管理员账号验证。
- 指标维度范围建议将缺失维度策略设为 `DENY`，让配置遗漏显式失败。
- 修改数据集输出字段、看板引用方式或角色成员后，重新检查相关规则是否仍然有效。
