# 业务在飞书表格里填数据，怎么自动进库？——DataY 一键打通飞书 ↔ 数据库

> 销售在飞书多维表格里登记线索，运营在里面维护工单，仓库在里面盘库存……
> 表格填得热火朝天，可到了月底做报表，数据还躺在飞书里。
> 导出、清洗、再导入，下个月重复一遍——**人肉 ETL，该结束了。**

---

## 一、一个每天都在发生的场景

销售在**飞书多维表格**里登记线索，运营在里面维护工单，仓库在里面盘库存……

一行行数据填得热火朝天，可到了月底要做报表时，数据团队才发现：**数据还躺在飞书的表格里。**

于是就有了这样一幕：

> 业务同学：把这个月的线索表发我一下。
> 数据同学：导出 Excel，清洗半天，再手动导入数据库……
> 下个月，重复一遍。

飞书多维表格解决了「**协作填写**」，却没有解决「**数据流转**」。表格越用越多，导出导入的活儿也越堆越多——**费时、易错、还不可持续。**

如果能让飞书表格里的数据**自动、定时、增量地流进数据库**，甚至还能**反向把库里的数据写回飞书**，是不是就不用再受这份罪了？

**DataY，就是为这类场景准备的。**

---

## 二、DataY 怎么解：两个组件，打通飞书 ↔ 数据库

DataY 内置了两个即插即用的组件：

| 组件 | 方向 | 作用 |
|------|------|------|
| `FeishuBitableInput` | 飞书 → 数据库 | 读取多维表格记录，写入 MySQL / PostgreSQL 等 |
| `FeishuBitableOutput` | 数据库 → 飞书 | 把数据库数据写回多维表格 |

**双向打通，全程不用写一行同步代码。**

- 飞书 → 库：`FeishuBitableInput` → `StreamJdbcOutput`
- 库 → 飞书：`StreamJdbcInput` → `FeishuBitableOutput`
- 中间还能插一个 `DuckDBSql` 组件，顺手把数据清洗、转换、聚合掉。

---

## 三、三个让你眼前一亮的能力

### ① 增量同步，不再全量重跑

飞书表格数据一多，每次都全量同步既慢又重。DataY 支持增量：

```json
{ "incrColumn": "last_modified_time" }
```

首次跑全量，之后只同步**新增或修改**的记录，增量状态由引擎自动持久化，重启后自动续接。数据库写入压力瞬间降下来。

> 说明：飞书暂不支持服务端按「最后更新时间」过滤，组件采用「拉取全部记录 + 本地按时间戳过滤」，因此每次仍会拉全量数据，但**只向下游发送变更记录**，写入压力显著下降。

### ② 自动判断新增还是更新，幂等不重复

`FeishuBitableOutput` 会看记录里有没有 `record_id`：有就**更新**（batch_update），没有就**新增**（batch_create）。配合唯一索引，轻松实现「**已存在则更新、不存在则插入**」：

```sql
ALTER TABLE `lead` ADD UNIQUE KEY uk_record_id (record_id);
```

### ③ 复杂字段自动扁平化，中文列名直接写

飞书里的人员、附件、链接、多选等复杂字段，组件会自动拍平成简单值；中文列名在 MySQL 里也能直接落库，不用再手动改名。

## 四、上手有多简单？

一个 JSON 配置文件，`java -jar` 一跑就完事：

```json
{
  "units": [
    {
      ".id": "FeishuBitableInput",
      ".name": "FeishuBitableInput",
      "appId": "cli_xxxxxxxx",
      "appSecret": "your-secret",
      "appToken": "EEmSbfNF8aD2RcsP26CcU3Bvnee",
      "tableId": "tblpjHsRMt8moPj8",
      "incrColumn": "last_modified_time"
    },
    {
      ".id": "StreamJdbcOutput",
      ".name": "StreamJdbcOutput",
      "table": "lead",
      "model": "append"
    }
  ],
  "connections": [
    { "sourceId": "FeishuBitableInput", "targetId": "StreamJdbcOutput" }
  ]
}
```

```bash
java -jar datay-core-*.jar feishu-to-mysql-task.json
```

想要更省事？打开 **DataY Web 可视化画布**，从左侧组件面板直接拖出「飞书多维表格」节点，连线、填参数、双击配置，全程鼠标搞定。再挂上 **Cron 定时调度**，每天凌晨自动把飞书数据搬进库。

## 五、这些场景，简直是为它量身定制

- **线索 / 工单沉淀**：业务在飞书填报，数据自动进库，CRM、报表实时取数；
- **库存 / 台账对账**：飞书表格当录入端，数据库当权威源，双向核对；
- **指标回写**：数仓算好日报 / 周报，自动写回飞书多维表格，业务打开就能看；
- **轻量数据中台**：飞书做前端采集，DataY 做清洗调度，DuckDB 做高性能分析，最后智能问数一句话出报表。

---

## 六、为什么是 DataY

- **一个 JAR 就够**：内嵌 DuckDB，**2 核 4G** 跑通完整数据链路，拒绝组件地狱；
- **零依赖启动**：10 分钟搭好环境，不用专职大数据工程师；
- **流批一体**：全量、增量、CDC 实时，按需切换；
- **一体化平台**：数据集成 → 维度建模 → 任务调度 → 高性能数仓 → 智能问数，闭环全有。

飞书负责让业务**填得爽**，DataY 负责让数据**流得通**。这两件事，终于可以同时做到了。
