# 数据服务应用市场（数据应用资产包）

> 把一个租户里已经开发完成的**数据模型、指标、ETL 任务、SQL 任务、数据源、编排任务**打包成一份
> 可移植的「数据应用资产包」；其它租户拿到资产包后一键初始化，即可在自己的租户里得到一套完整可用的数据应用。

入口：顶部菜单 **数据应用 → 应用市场**（`/app-package`）。

---

## 1. 为什么需要资产包

平台里的数据资产是**跨对象强引用**的：指标挂在事实模型上，事实模型挂在数据源上，
ETL 节点里写着数据源 ID 和模型 ID，SQL 任务里写着数据源 ID，编排任务里写着子任务的 Job ID。
直接导出一批表的行数据，换一个租户导入就会全部串号。

资产包解决两件事：

1. **可移植**：包内所有引用都使用「包内逻辑 ID」（`oldId` / `xxxOldId`），与数据库自增 ID 解耦，
   因此同一份包可以在任意租户里反复初始化。
2. **初始化时统一做 ID 替换**：安装到目标租户时建立「旧 ID → 新 ID」映射表，把所有引用改写成新生成的 ID，
   **数据源还会优先复用目标租户已有的连接**，不会重复创建。

## 2. 资产包结构

资产包是一份 JSON 文件（`.json`），结构如下（字段与 `AppPackageContent` 一一对应，null 字段省略）：

```jsonc
{
  "packageFormat": "datay-app-package",
  "formatVersion": "1.0",
  "meta": { "name": "...", "code": "...", "category": "零售电商", "version": "1.0.0", "source": "TENANT" },

  "dataSources":       [ { "oldId": 1600, "key": "名称|类型|URL", "name": "...", "type": "DUCKDB", "url": "...", "username": "...", "password": "..." } ],
  "modelDirectories":  [ { "oldId": 1002, "name": "公共维度", "parentOldId": 1000, "sortOrder": 1 } ],
  "models":            [ { "oldId": 3100, "dataSourceOldId": 1600, "directoryOldId": 1004,
                           "fields": [ { "oldId": 4000, "fieldName": "order_date_key",
                                         "dimensionModelOldId": 3000, "dimensionFieldOldId": 4001 } ] } ],
  "metricDirectories": [ { "oldId": 2510, "name": "销售指标" } ],
  "metrics":           [ { "oldId": 2610, "directoryOldId": 2510, "factModelOldId": 3100,
                           "metricType": "ATOMIC", "formula": "SUM(order_amount)",
                           "filterConfig": { "conditions": [ { "type": "DIMENSION", "dimensionModelId": 3002, "dimensionModelCode": "dim_store", "dimensionFieldName": "city" } ] } } ],
  "etlTasks":          [ { "oldId": 6000, "jobOldId": 7000,
                           "nodes": [ { "type": "JdbcInput", "config": { "sourceId": 1600 } },
                                      { "type": "ModelWrite", "config": { "modelId": 3100 } } ],
                           "edges": [ { "source": "n1", "target": "n2" } ] } ],
  "sqlJobs":           [ { "oldId": 7100, "type": "SQL", "jobContext": { "dataSourceId": 1600, "schema": "main", "sql": "..." } } ],
  "dagJobs":           [ { "oldId": 7200, "type": "DAG",
                           "jobContext": { "jobs": [ { "id": 7000 }, { "id": 7100 } ],
                                           "jobDepends": [ { "parentJobCode": 7000, "childJobCode": 7100 } ],
                                           "nodeLayout": [ { "jobId": 7000, "xAxis": 100, "yAxis": 100 } ] } } ],
  "otherJobs":         [],
  "jobDepends":        [],
  "summary":           { "dataSources": 1, "models": 10, "metrics": 12, "total": 121 }
}
```

`summary` 由服务端在导出/加载时按实际内容重算，手写资产包时可以省略。

## 3. 导出

**应用市场 → 导出数据应用资产包**（`/app-package/export`）：

1. 填写名称、编码、说明、业务场景分类与版本；
2. 分别勾选要打包的数据源、数据模型、指标、ETL 任务、SQL 任务、编排任务；
3. 保持「包含引用」开启时，服务端会自动补齐被引用的资产：
   - 指标 → 事实模型、`filterConfig` 里按编码引用的维度模型；
   - 模型 → 绑定的数据源、字段关联的维度模型；
   - ETL 任务 → 节点配置里的 `sourceId`（数据源）与 `modelId`（数据模型）；
   - SQL 任务 → `jobContext.dataSourceId`；
   - 编排任务 → 递归纳入所有子任务（ETL / SQL / Shell 等）。
4. 生成后资产包登记到市场，可随时下载 JSON 分发给其它租户。

接口：`POST /api/app-packages/export` → 返回资产包内容；`GET /api/app-packages/{id}/content` 下载文件。

## 4. 初始化与 ID 替换

**应用市场 → 初始化**（或资产包详情页），也可以直接**上传资产包文件**初始化。
初始化对话框支持：冲突策略、是否顺带上线任务、为包内数据源指定绑定到目标租户的某个已有数据源。

### 4.1 数据源：先复用，再新建

| 顺序 | 规则 | 结果标记 |
| --- | --- | --- |
| 1 | 调用方在「数据源绑定」里显式指定了目标数据源 | `MAPPED` |
| 2 | 目标租户已存在 `名称 + 类型 + 连接地址` 完全相同的数据源 | `REUSED` |
| 3 | 都没有 | `CREATED`（新建数据源） |

无论哪种情况都会登记 `oldId → newId`，后续所有引用都改写成 `newId`。

### 4.2 各类引用的替换规则

| 资产 | 需要替换的引用 | 规则 |
| --- | --- | --- |
| 数据模型 | `dataSourceId`、`directoryId` | 数据源映射 / 目录按名称复用或新建 |
| 模型字段 | `dimensionModelId`、`dimensionFieldId` | 先建全部模型与字段，再回填字段级映射 |
| 指标 | `factModelId`、`filterConfig.dimensionModelId`、`filterConfig.dimensionModelCode` | 业务限定的维度 ID 与编码同步改写；衍生指标 `${code}` 引用在编码被重命名时同步改写 |
| ETL 任务 | 节点 `config.sourceId`（数据源）、`config.modelId`（模型） | 递归重写节点配置 JSON；任务重新生成自己的调度 Job |
| SQL 任务 | `jobContext.dataSourceId` | 重写为新的数据源 ID |
| 编排任务 | `jobContext.jobs[].id`、`jobDepends[].parentJobCode/childJobCode`、`nodeLayout[].jobId` | 按 Job 映射重写；引用了包外任务时移除该节点并给出提示 |

### 4.3 冲突策略

导入前先按编码判断目标租户是否已有同名资产，命中时按策略处理：

- **RENAME（默认）**：编码追加 `_copy`、`_copy2`…，任务名称追加 `(副本)`；引用关系同步改写，保证包内自洽。
- **SKIP**：跳过该资产。被跳过的模型会导致其指标一并跳过，被跳过的任务会导致编排里的对应节点被移除——
  这些都会写入初始化结果的 `warnings`，不会静默丢数据。

导入的资产一律为**离线**状态，除非显式勾选「初始化后直接上线」。

### 4.4 初始化结果

返回并展示：

- `counts`：各类资产的创建/复用/跳过数量；
- `dataSources`：每个数据源是 `CREATED` / `REUSED` / `MAPPED`，以及 `oldId → newId`；
- `idMapping`：各类资产的完整 ID 对照表；
- `warnings`：重命名、跳过、引用了包外资产等提示。

每次初始化都会写入 `dp_app_package_instance`，在市场「初始化记录」页签可回溯（失败也会记录，独立事务写入）。

## 5. 系统预制业务场景包

> **平台不再通过数据库迁移脚本预置任何业务数据。**
> 数据源、模型、指标、ETL / SQL / 编排任务只来自资产包，`app-packages/*.json` 是唯一的
> 「演示数据 / 场景交付」载体：新租户登录后是干净的，到应用市场初始化一个场景即可获得完整可用的数据应用。

系统预制包随程序发布，启动时由 `SystemAppPackageLoader` 扫描
`datay-web/src/main/resources/app-packages/*.json` 自动登记为 `packageType=SYSTEM`
（`tenant_id` 为空，所有租户可见），以资产包编码为唯一键做幂等 upsert。

当前预置两个场景：

| 文件 | 场景 | 内容 |
| --- | --- | --- |
| `ecommerce-sales-app.json` | 零售电商 | **完整业务场景**：业务源库 + 数仓 2 个数据源；9 个模型 = 6 个维度（时间维度、区域/品类 2 个三级层级维度、门店/商品/客户 3 个普通维度）+ 1 个 DWD 事实 + DWS 汇总 + ADS 应用；80 个字段、12 个指标（7 原子 + 5 衍生，含业务限定指标）；7 个 ETL（6 个表同步 + 1 个自定义 SQL 抽取）、3 个 SQL 任务，并用 1 个编排任务把 10 个任务统一编排成日更链路 |
| `datay-quickstart-app.json` | 快速入门 | **教学场景**：业务源库 + 数仓 2 个数据源；5 个模型覆盖时间维度 / 层级维度 / 普通维度 / DWD 事实 / ADS 应用；4 个 ETL（标准「源库 → 模型写入」流程）、2 个 SQL 任务（源库样例数据 + ADS 汇总）、1 个编排任务串起全部 6 个任务 |

两个场景的编码互不冲突（快速入门用 `qs_` 前缀），可以同时初始化到同一个租户。

**新增一个业务场景**只需要往该目录丢一个符合
[资产包编写规范](资产包编写规范.md) 的 JSON 文件，无需改数据库脚本。
`AppPackagePresetTest` 会在构建时校验所有预置包的格式、包内引用完整性，以及 ETL 节点类型是否真实注册。

### 5.1 初始化后怎么跑通

1. 应用市场 → 选中场景 → **初始化**（默认冲突策略 `RENAME`，全部资产以离线状态导入）；
2. 「任务编排」里找到该场景的编排任务 → **执行一次**；
   编排会依次执行：SQL（生成源库样例数据）→ 各维度 ETL → 事实 ETL → DWS/ADS SQL；
3. 回到「指标管理 / 智能问数」，可以直接按维度、层级、时间查询指标。

## 6. 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/app-packages` | 浏览市场（系统预制包 + 本租户的包），支持 `search` / `source` / `category` |
| GET | `/api/app-packages/categories` | 市场里出现过的业务场景分类 |
| GET | `/api/app-packages/export-options` | 导出向导可选资产 |
| GET | `/api/app-packages/{id}` | 资产包详情（含内容 JSON） |
| GET | `/api/app-packages/{id}/content` | 下载资产包 JSON |
| POST | `/api/app-packages/export` | 按选择导出资产包 |
| POST | `/api/app-packages/import` | 按 `packageId` 或上传的 `content` 初始化 |
| POST | `/api/app-packages/{id}/init` | 用市场中某个资产包初始化 |
| DELETE | `/api/app-packages/{id}` | 删除本租户导出的资产包（系统预制包不可删除） |
| GET | `/api/app-packages/instances` | 当前租户的初始化记录 |
