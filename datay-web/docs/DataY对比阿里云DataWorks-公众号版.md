# 一个 JAR，还是一朵云？DataY 与阿里云 DataWorks 选型对比

> 同样叫「数据平台」，DataWorks 卖的是规模化治理与全托管，DataY 卖的是低门槛、可私有化和一条龙闭环。选型的关键，不是谁功能多，而是你的成本结构适合哪一种。

---

## 01 先把两个产品放回各自的位置

DataWorks 和 DataY 经常被放在同一张对比表里，但它们其实出生在两个完全不同的世界。

**阿里云 DataWorks** 脱胎于阿里巴巴集团内部的数据中台实践，2010 年前后以「大数据开发套件」起步，后来逐步长成覆盖数据集成、数据开发、数据建模、数据质量、数据地图、数据服务、安全治理的一站式 PaaS 平台。它的默认运行方式是阿里云上的全托管服务，计算交给 MaxCompute、Hologres、E-MapReduce、AnalyticDB、Flink 等引擎，DataWorks 负责开发、调度、治理和协作。

**DataY** 则是一个开源、可私有化部署的轻量数据平台。它把数据集成引擎、调度引擎、元数据与 Web 控制台打成一个 JAR，内嵌 DuckDB 作为默认分析引擎，目标是让一台 2 核 4G 的机器也能跑通「接入 → 建模 → 开发 → 调度 → 问数」的完整链路。

一句话概括两者的差别：

> DataWorks 用云上的计算资源和平台能力，换走你的运维复杂度；
> DataY 用一套极简运行时，换走你的软件采购成本和数据出境顾虑。

这不是「谁替代谁」的问题，而是两种成本结构的交换。

### 一张表看懂

| 维度 | DataY | 阿里云 DataWorks |
| --- | --- | --- |
| 产品形态 | 开源软件，可私有化 / 内网 / 边缘部署 | 阿里云全托管 PaaS，另有专有云形态 |
| 起步门槛 | 一个 JAR，2 核 4G 可跑通全链路 | 阿里云账号 + 计算引擎 + 资源组 + 网络打通 |
| 默认计算引擎 | 内嵌 DuckDB，可外挂 Doris / ClickHouse | MaxCompute / Hologres / EMR / ADB / Flink 等 |
| 核心强项 | 轻量、闭环、可嵌入、AI 原生、数据主权 | 规模、治理、多引擎、企业级安全与协作 |
| 典型用户 | 中小企业、部门级团队、开发者、信创 / 内网场景 | 中大型企业、阿里云深度用户、集团级数据中台 |
| 计费方式 | Apache 2.0 免费，商业服务可选 | 版本订阅 + 计算 + 存储 + 资源组 + 增值模块 |
| 运维责任 | 用户自己（或购买商业支持） | 平台侧托管，用户主要管权限与成本 |

## 02 架构差异，决定了后面所有差异

### DataWorks：控制面与计算面分离

DataWorks 的架构可以粗略理解为「一个控制面 + 多个计算面」：

```
DataWorks 控制面
（开发 / 调度 / 元数据 / 质量 / 治理 / 权限）
        │
        ├── MaxCompute    离线数仓
        ├── Hologres      实时数仓
        ├── E-MapReduce   Hadoop / Spark / Flink
        ├── AnalyticDB    分析型数据库
        └── Flink         实时计算
        │
        ▼
Serverless / 独享资源组（数据集成、调度、数据服务）
```

这套架构的好处很直接：

- 计算与存储可以独立伸缩，PB 级数据也能扛；
- 一个平台统管多种引擎，团队不用为每种引擎搭一套开发工具；
- 开发、生产环境隔离，代码评审、发布管控、操作审计是平台内置能力；
- 数据集成通过资源组打通公网、VPC、IDC，复杂网络有成熟方案。

代价也很直接：

- 你必须接受阿里云的技术栈与计费体系；
- 计算、存储、资源组、版本订阅分别计费，账单需要专门治理；
- 平台能力很全，但小团队往往用不到一半。

### DataY：把整条链路塞进一个运行时

DataY 的架构更接近「一体化应用」：

```
┌─────────────────────────────────────────────┐
│                DataY Web                     │
│  数据源 / ETL 画布 / 调度 / 建模 / 指标 / 问数  │
├─────────────────────────────────────────────┤
│                DataY Core                    │
│  流批一体集成引擎 + 自动建表 + CDC + 质量检核   │
├─────────────────────────────────────────────┤
│  内嵌 DuckDB  │  H2 / MySQL  │  Quartz 调度   │
└─────────────────────────────────────────────┘
        │                    │
        ▼                    ▼
   本地文件 / MinIO      外部引擎（可选）
                        Doris / ClickHouse / DuckLake / Polaris
```

它的设计取舍是：**默认把所有东西都装好，需要规模时再外挂。**

- 元数据默认落 H2，生产可换 MySQL；
- 调度用 Quartz，单机即可跑，也可以拆成 master / worker；
- 计算默认走 DuckDB，数据量大时把目标端换成 Doris、ClickHouse 或数据湖；
- 集成引擎可以脱离 Web 单独运行，用 JSON 定义任务，也可以嵌入 Java 应用。

这套架构的上限不如「控制面 + 多引擎」，但下限极低：不用装 Hadoop、不用配资源组、不用先买一个数仓，下载 JAR 就能开始。

## 03 八项能力逐条对比

### 3.1 数据集成：广度对阵密度

DataWorks 的数据集成是它最成熟的能力之一。官方口径支持 50 多种异构数据源，覆盖关系型数据库、数仓、NoSQL、文件存储、消息队列，支持离线同步、实时同步、全增量一体化，并通过 Serverless 资源组或独享资源组运行。它擅长的是「复杂网络 + 大规模 + 多类型数据源」的组合。

DataY 支持三十余种数据源，数量上不占优势，但覆盖了中小企业最常见的几类：

- **关系型**：MySQL 系、PostgreSQL 系、Oracle、SQL Server、MariaDB、达梦、SAP HANA；
- **分析型**：DuckDB、Doris、ClickHouse、GreenPlum、YMatrix；
- **时序 / 缓存 / 消息**：TDengine、Redis、Kafka、MQTT；
- **文件与对象存储**：本地文件、CSV、Excel、Parquet、MinIO；
- **数据湖**：DuckLake、Apache Polaris（Iceberg REST Catalog）；
- **CDC**：MySQL Binlog、PostgreSQL 逻辑复制、Oracle LogMiner、达梦 LogMiner、SQL Server CDC、MongoDB Change Streams。

DataY 的差异化在于「密度」：

- 可视化拖拽画布编排 ETL，也可以用一份 JSON 直接跑；
- 自动建表、DDL 转换，源表改字段能同步到目标；
- 跨库数据比对：按主键关联两侧表，用 DuckDB SQL 算差异，结果写本地或 MinIO；
- HTTP、飞书多维表格、MQTT 这类「非典型数据源」也能进同一条链路；
- 集成引擎可嵌入、可 CLI 运行，不强制依赖 Web 平台。

**怎么选**：数据源种类多、跨 VPC / IDC、需要 PB 级吞吐，DataWorks 更稳；数据源集中在主流数据库、希望一条画布从 API 接到数仓，DataY 更轻。

### 3.2 数据开发与调度：企业治理对阵极简编排

DataWorks 的 DataStudio 是典型的「企业级 IDE」：支持 MaxCompute、EMR、CDH、Hologres、AnalyticDB、ClickHouse 等多种引擎；提供开发 / 生产隔离、版本管理、代码评审、冒烟测试、发布管控、操作审计；调度侧有基线、智能诊断、自动运维、值班表、移动运维等能力。官方披露其调度能力经过阿里集团内部千万级任务的验证。

DataY 的调度走的是另一条路：

- Quartz Cron，精确到秒；
- DAG 工作流，支持嵌套工作流；
- 任务类型覆盖 ETL、SQL、Shell、DAG；
- 上线 / 下线、手动触发、失败重试、实例终止；
- 单机 `standalone` 直接跑，也可以拆成 `master` / `worker`，多 master 通过 Redis 做 Leader 选举，worker 可水平扩展；
- 并发数、队列容量、Quartz 线程数都可配置，默认 50 并发、50 队列。

它没有基线管理、智能诊断、自动运维这些「平台级」功能，但把 80% 的日常调度需求做进了同一个 JAR 里。

**怎么选**：多团队协作、需要发布管控与值班体系，DataWorks 更合适；几十到上千条任务、希望今天装明天用，DataY 的复杂度更低。

### 3.3 建模与指标：方法论对阵闭环

DataWorks 的智能数据建模是一个独立增值模块，包含数仓规划、数据标准、维度建模、数据指标四块。它沉淀了阿里数据中台的建模方法论，支持逆向建模、Excel 导入、FML 建模，并能与 DataStudio 打通自动生成 ETL 代码。优势是「标准」和「方法论」，适合从零搭建企业级数仓规范。

DataY 的建模更偏「小而完整」：

- 星型 / 雪花模型，可视化定义事实表与维度表关联；
- 普通维度、层级维度、时间维度三种类型；
- 事实表外键一键关联维度，指定时间周期字段后，指标自动获得业务语义；
- 维度 / 事实模型可物化建表，直接落到内嵌 DuckDB；
- 原子指标、衍生指标、公共指标查询统一口径；
- 建模、指标、问数共用同一套语义层，指标口径不会在三个系统里各说各话。

DataWorks 的建模强在「规范怎么定」，DataY 的建模强在「定完立刻能用」：模型建完可以物化，指标建完可以直接问数，不需要在建模工具、开发平台、BI 之间来回切换。

**怎么选**：需要数据标准、命名词典、跨部门模型共享，DataWorks 更完整；希望一周内把维度、指标、问数跑通，DataY 的路径更短。

### 3.4 数据质量：规则库对阵数据流门禁

DataWorks 的数据质量提供 30 多种预设的表级、字段级和自定义模板，支持质量大盘、规则配置、质量报告、告警订阅，企业版还支持动态阈值和自定义规则模板。它最擅长的是「在调度链路里自动拦截脏数据」，不让问题数据污染下游。

DataY 的数据质量分两块：

- **质量规则**：表级（行数下限、行数范围、组合唯一、自定义 SQL）和字段级（非空、唯一、范围、枚举、正则、长度、时效、自定义 SQL）；
- **检核任务**：选数据源和表，绑定规则后立即执行，结果写文件存储，支持下载汇总和问题数据抽样。

更有特色的是 ETL 内的「数据质量检核」组件：

- `STREAM` 模式逐批检核，通过后立即下发，适合在流中间做门禁；
- `FULL` 模式先落 DuckDB，上游结束后全量检核，再决定是否下发；
- `ERROR` 规则不达标时组件抛异常，任务直接失败。

DataWorks 的质量体系更厚，DataY 的质量能力更贴近「数据流里的一道闸」。

**怎么选**：需要质量大盘、动态阈值、跨团队质量报告，DataWorks 更强；只需要在关键链路上拦住脏数据，DataY 够用且更直接。

### 3.5 数据地图与血缘：治理资产对阵全域视图

DataWorks 的数据地图以元数据采集和检索为基础，提供表详情、字段信息、产出信息、血缘、质量、预览，并支持数据专辑、类目管理、资产治理、标签管理。企业版还能做资产分析、治理计划、自动化治理。它的定位是「数据资产治理入口」。

DataY 的数据地图把平台内所有对象拉进一张图：

- 数据源、表 / 字段、ETL 任务、数据模型、指标、数据集、看板、API、质量任务；
- 默认用 ECharts 关系图展示全量资产与上下游关系；
- 支持按类型、数据源筛选和聚焦；
- 支持名称、编码、注释全文检索与关键字高亮；
- 配合全链路血缘，可以从前端看板一路追到源表和 ETL 任务。

DataWorks 胜在治理深度和元数据规模，DataY 胜在「一个平台里的东西都能在一张图上看清」。

**怎么选**：需要跨系统元数据采集、资产分级、治理闭环，DataWorks 更专业；希望快速看清自己平台里的资产关系，DataY 更直观。

### 3.6 数据服务：API 网关对阵轻量服务化

DataWorks 的数据服务可以把表零代码或脚本方式生成 API，支持 API 注册、授权、过滤器、数据推送，并一键发布到 API 网关，具备调用计量和资源隔离。它适合把数仓能力开放给多个业务系统。

DataY 也提供数据服务能力：注册已有 API、配置 Token 认证与动态参数、在线调试、查看完整响应体。它更偏「平台内自用」和「快速把查询暴露出去」，没有 API 网关那样的计量、限流、订阅生态。

**怎么选**：需要对外开放、计量计费、网关级治理，DataWorks 更合适；只需要把内部数据快速变成接口，DataY 更轻。

### 3.7 安全与权限：合规体系对阵够用就好

DataWorks 的安全中心是典型的企业级配置：工作空间与租户角色、自定义角色、云 SSO、审批中心、数据访问控制、数据保护伞（分类分级、敏感数据识别、脱敏、水印溯源）、Ranger 集成、操作审计。它解决的是「几百人、多部门、强合规」的问题。

DataY 的权限体系更朴素：

- 登录，角色控制菜单与接口；
- 维度数据权限：按角色限制指标查询能看到的维度成员；
- 数据集数据权限：按角色限制数据集输出行；
- 两类权限可叠加，规则在服务端拼进 SQL，前端改参数绕不过去；
- 多租户隔离。

它没有数据分类分级、动态脱敏、水印、审批流这些能力。对中小企业够用，对金融、政务、大型集团则偏薄。

**怎么选**：有明确合规、审计、脱敏要求，DataWorks 更稳；内部使用、权限边界清晰，DataY 的基础能力够。

### 3.8 AI 能力：云上 Copilot 对阵模型无关的 Agent

DataWorks 这两年在 AI 上投入很大：Data Agent、Copilot、ChatBI、代码编程助手、快捷 AI 操作、知识库、MCP 扩展，覆盖「自然语言写 SQL」「自然语言查数」「自然语言操作平台」。优势是与阿里云模型和平台数据天然打通，开箱即用。

DataY 的 AI 能力是「原生 + 可替换」：

- 智能问数：自然语言 → 指标 → 维度 → 时间过滤 → 取数，RAG 本地向量索引保证口径不跑偏；
- AI SQL 助手、ETL 任务设计助手、看板设计助手、Java 脚本助手；
- MCP Harness：通过 `/mcp/datay` 把数据源、数据服务、ETL 任务、数据模型的增删改查与运行动作暴露给 Agent；
- 同一端点还提供指标问数和指标定义管理，与页面保存共用一套校验；
- AI 能力兼容 OpenAI Chat Completions 协议，OpenAI、DeepSeek、通义千问、Ollama 都能接，默认 DeepSeek，也可以完全跑本地模型。

DataWorks 的 AI 更像「平台内置助手」，DataY 的 AI 更像「可被外部 Agent 操作的数据平台」。

**怎么选**：希望 AI 能力开箱即用、与云上数据无缝衔接，DataWorks 更省心；希望模型自主可控、Agent 能直接操作平台对象，DataY 更开放。

## 04 成本：免费的最贵，还是订阅的最贵？

先看 DataWorks 的公开报价（中国站，按月，具体以官网为准）：

| 版本 | 公开列表价 | 主要增量 |
| --- | --- | --- |
| 基础版 | 0 元 / 月 | 核心开发调度，功能与配额受限 |
| 标准版 | 2,500 元 / 月 | 分支 / 循环节点、基线、代码搜索、血缘等 |
| 专业版 | 5,000 元 / 月 | Check 节点、代码评审、值班表、智能诊断 |
| 企业版 | 20,000 元 / 月 | 自定义角色、SSO、扩展程序、动态阈值、数据保护伞完整能力 |

但版本订阅只是账单的一部分。真正的大头通常在三处：

1. **计算引擎**：MaxCompute、Hologres、EMR、ADB 按 CU / 存储 / 时长计费；
2. **资源组**：数据集成、调度、数据服务使用的 Serverless 或独享资源组；
3. **增值模块**：智能数据建模需要单独购买，API 调用超出免费额度后按量计费，短信 / 电话告警也有额外费用。

一个 20 人左右的数据团队，如果选标准版 + 中等规模 MaxCompute + Serverless 资源组 + 建模模块，年账单落在数万到数十万元区间并不罕见。具体数字取决于数据量、任务数和查询并发，建议用阿里云官方报价器测算。

DataY 的成本结构简单得多：

| 项目 | 估算 |
| --- | --- |
| 软件许可 | 0 元（Apache 2.0） |
| 服务器 | 一台 4C8G / 8C16G 云主机，每年约 3,000～15,000 元 |
| 存储 / 备份 | 本地盘或对象存储，每年数百到数千元 |
| 外部引擎（可选） | 已有 Doris / ClickHouse 可直接复用 |
| 商业支持（可选） | 按服务内容单独报价 |

同样规模的团队，DataY 的软件与基础设施年成本通常可以控制在一万元上下；代价是你要自己负责部署、备份、监控和升级，或者购买商业支持来补这部分人力。

**所以成本对比不能只看软件费，而要看「软件 + 计算 + 运维人力」的总和。**

- DataWorks 把运维成本打包进了订阅和云资源，账单透明但随规模增长；
- DataY 把软件成本压到接近零，把运维责任交还给用户；
- 当数据量中等、已有服务器、且能接受基础运维时，DataY 的总成本优势非常明显。

## 05 部署、数据主权与信创

DataWorks 的主战场是阿里云公共云，覆盖杭州、上海、北京、深圳、成都、香港、新加坡、东京、法兰克福、硅谷等地域。它也提供专有云形态，但整体仍是一个「平台级」交付，适合有云平台团队的企业。

DataY 的部署形态更灵活：

- 一台笔记本、一台内网服务器、一个边缘盒子都能跑；
- 数据不出内网，适合政务、军工、医疗、制造等对数据主权敏感的场景；
- 调度 master / worker 可分离，单机与集群同一套代码；
- 支持达梦等国产数据库，可配合信创环境做适配；
- 代码开源，可审计、可二次开发、可做多租户和 SSO 改造。

如果你的约束是「数据不能上公有云」，DataWorks 的公共云版本直接出局，DataY 则是为这个场景设计的。

## 06 选型建议：先问四个问题

### 问题一：你的数据在哪？

- 已经在阿里云上，用 MaxCompute / Hologres / EMR：优先 DataWorks，网络、权限、计费都在一个体系里。
- 数据在 IDC、内网、边缘，或不能出境：优先 DataY。
- 混合云：可以用 DataY 做边缘采集和前置处理，DataWorks 做中心数仓。

### 问题二：你的规模有多大？

- PB 级、千万级任务、几百人协作：DataWorks 的规模能力更成熟。
- GB 到 TB 级、几十到上万条任务、几人到几十人：DataY 完全覆盖，且更省。

### 问题三：你的团队有谁？

- 有专职大数据平台团队，能管资源组、引擎、成本：DataWorks 能用出价值。
- 只有 Java / 数据开发，没有大数据运维：DataY 的零依赖启动更友好。
- 需要合规、审计、脱敏、审批：DataWorks 的安全体系更完整。

### 问题四：你要多快上线？

- 需要本周就把数据接进来、建好指标、做出看板：DataY 下载即用。
- 需要先做数仓规划、数据标准、跨部门模型评审：DataWorks 的方法论更成体系。

### 一张选型矩阵

| 场景 | 推荐 |
| --- | --- |
| 阿里云重度用户，已有 MaxCompute / Hologres | DataWorks |
| 集团级数据中台，多 BU、多租户、强治理 | DataWorks |
| 金融 / 政务，需要分类分级、脱敏、审批、审计 | DataWorks（或 DataY + 商业定制） |
| 中小企业，预算有限，无专职大数据团队 | DataY |

| 超大吞吐、50+ 数据源、跨地域同步 | DataWorks |

## 07 也要诚实地说说边界

**DataY 不适合什么？**

- 单机 DuckDB 有性能上限，超大规模并发查询需要外挂 Doris / ClickHouse 或数据湖；
- 数据源数量、社区生态、第三方连接器还不如 DataWorks 丰富；
- 企业级治理（分类分级、动态脱敏、水印、审批流、Ranger）能力较轻；
- 它不是托管服务，备份、高可用、升级需要自己负责，或购买商业支持；
- 基线管理、智能诊断、自动运维等平台级调度能力相对简单。

**DataWorks 不适合什么？**

- 小团队用基础版会被配额限制，用标准版以上又容易功能过剩；
- 账单随规模增长，计算、存储、资源组、版本、增值模块需要持续治理；
- 深度绑定阿里云生态，跨云和私有化不如开源方案灵活；
- 平台较重，学习和落地周期长，不适合「今天就想看到数据」的场景；
- 定制能力受产品边界约束，源码级改造不现实。

## 08 写在最后

DataWorks 代表的是「用钱买规模和治理」：它把阿里内部十几年的数据中台经验产品化，适合有规模、有合规要求、有云平台团队的企业。

DataY 代表的是「用极简换门槛」：一个 JAR、内嵌 DuckDB、2 核 4G 起步，把集成、建模、开发、调度、问数塞进同一条链路，适合想快速落地、又不想被组件和账单拖住的小团队。

两者不是替代关系。真正需要回答的问题不是「谁更强」，而是：

> 你愿意为规模付多少钱，又愿意为轻量承担多少运维？

想清楚这一点，选型其实并不难。

## DataY 轻量数据平台

**DataY 是一套开源、轻量的一体化数据平台**，理念很简单：

> 数据平台可以很小，功能不打折。

传统数据平台往往需要 Hadoop、Spark、Flink、ClickHouse 一整套组件，几十台机器起步，运维门槛高。DataY 选择另一条路：

- **一个 JAR**，自研流批一体数据集成引擎，拒绝组件地狱；
- **2 核 4G** 就能跑通「数据集成 → 数据建模 → 数据开发 → 任务调度 → 数据应用」的完整链路；
- 零依赖启动，10 分钟搭好开发环境；
- 内嵌 DuckDB 作为高性能分析引擎，同时支持 Doris、ClickHouse 等外部分析引擎；
- 调度 master 与执行 worker 可分可合，单机和集群同一套代码。

这里的「轻量」指的是**运行资源门槛低**，不是能力轻量。

DataY 由两块组成：

| 模块 | 定位 | 说明 |
| --- | --- | --- |
| **DataY Core** | 数据集成引擎 | 轻量、可嵌入、可扩展、流批一体；JSON 定义任务、自动建表、CDC 实时同步；可脱离 Web 独立运行或嵌入 Java 应用 |
| **DataY Web** | 可视化数据平台 | 拖拽式任务设计、任务调度、维度建模、指标管理、智能问数、分析看板 |

平台的核心能力包括：

- **数据集成**：MySQL、PostgreSQL、Oracle、SQL Server、Doris、ClickHouse、DuckDB 等二十余种数据源，支持全量、增量与 CDC 实时同步；
- **数据湖**：支持 DuckLake、Apache Polaris（Iceberg REST Catalog），可直接浏览元数据、执行 SQL 与批量写入；
- **维度建模**：星型 / 雪花模型，普通维度、层级维度、时间维度，事实表外键一键关联；
- **任务调度**：Quartz Cron 精确到秒，DAG 工作流编排，失败重试与暂停恢复；
- **高性能数仓**：内嵌 DuckDB，列存 + 向量化，支持 DuckLake / Iceberg 数据湖，也可外挂 Doris / ClickHouse；
- **数据质量**：表级 / 字段级规则、自定义 SQL、ETL 流内质量门禁；
- **数据地图**：全域资产关系图、全文检索、全链路血缘；
- **智能问数**：自然语言 → 指标 → 维度 → 时间过滤 → 取数，一句话拿报表；
- **分析看板**：数据集管理、AI 生成看板、24 栅格设计器、大屏与嵌入分享；
- **AI 原生能力**：AI SQL 查询助手、ETL 任务设计助手、看板设计助手、智能问数助手、Java 脚本助手，以及面向 Agent 的 MCP Harness。

AI 能力兼容 OpenAI Chat Completions 协议，OpenAI、DeepSeek、通义千问、Ollama 等模型服务都可以对接。默认使用 DeepSeek，启动时通过 `DATAY_AI_API_KEY` 配置即可。

